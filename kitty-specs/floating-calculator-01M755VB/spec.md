## Episode Design *(공통 엔진 도구 + 기존 에피소드 02-race-engineer 적용: 바뀌는 항목만)*

### 1. Role Setting

N/A — 역할은 바뀌지 않는다. 레이스 엔지니어가 드라이버에게 무전으로 보낼 숫자를 계산할 때, 피트월에 있는 계산기를 쓰는 것과 같은 도구가 화면에 생긴다.

### 2. Math Concepts → 도구 요구사항

이 미션은 새 수학 개념을 가르치지 않는다 (선수 지식 없음). 대신 계산기가 지켜야 할 **식 계산 규칙**을 정한다. 같은 식에 다른 값이 나오면 판정 오차(±0.02~3)와 맞물려 "맞게 계산했는데 틀림"이 생기므로, 아래 규칙은 반드시 그대로 구현한다 (사람 결정 2026-11-11).

**쓸 수 있는 것**: 숫자(소수점 포함), π, `+` `−` `×` `÷`, `^`(거듭제곱), `√`(제곱근), `(` `)`. sin·cos 등 삼각함수는 **범위 밖** (두 에피소드 모두 각도를 숫자로 입력하지 않고, 도/라디안 모드가 혼동을 만듦. 필요한 에피소드가 생기면 그때 추가).

**우선순위** (위가 먼저 계산됨):

| 순위 | 규칙 | 예 (값은 `answers.md`) |
|---|---|---|
| 1 | 괄호 `( )`, 숫자, π | |
| 2 | `√`는 **바로 뒤에 오는 숫자·π·괄호 하나**에만 적용된다. `√√16`처럼 겹쳐 쓸 수 있다 | `√9+7`, `√2π` |
| 3 | `^`는 **오른쪽부터** 계산한다. 지수 자리에는 `−`를 붙일 수 있다 | `2^3^2`, `2^-1` |
| 4 | 곱하기 기호 생략: 두 항이 연산자 없이 붙어 있으면 곱한다 (`2π`, `3(4+5)`, `(1+2)(3+4)`, `2√9`). **붙여 쓴 곱은 `×`·`÷`보다 먼저** 계산한다 | `1÷2π`, `6÷2(1+2)`, `2π^2` |
| 5 | 단항 마이너스 `−`: `^`보다 나중에 적용된다. 식 맨 앞, 여는 괄호 뒤, 다른 연산자 뒤에 올 수 있다 | `-2^2`, `2×-3` |
| 6 | `×` `÷`: 왼쪽부터 | `8÷4÷2` |
| 7 | `+` `−`: 왼쪽부터 | `10−4−3` |

**오류로 처리하는 식** (값을 내지 않고 이유를 보여 줌). 이유는 다섯 가지다:

| 이유 (ko / en) | 해당하는 식 |
|---|---|
| 식을 확인하세요 / Check the expression | 빈 식, 빈 괄호 `()`, 연산자나 `√`로 끝남, 연산자로 시작(`−` 제외), 소수점이 둘인 숫자(`1.2.3`), 소수점만 있는 숫자(`.`) |
| 괄호 짝이 맞지 않습니다 / Brackets don't match | 여는 괄호와 닫는 괄호의 수나 순서가 맞지 않음 |
| 0으로 나눌 수 없습니다 / Can't divide by zero | 0으로 나누기, 0의 음수 거듭제곱(`0^-1`) |
| 실수로 계산할 수 없습니다 / Not defined for real numbers | 음수의 제곱근, 음수의 정수가 아닌 거듭제곱(`(-8)^(1÷3)`), `0^0` (교과서는 a ≠ 0일 때만 a⁰ = 1로 정의) |
| 결과가 너무 큽니다 / Result too large | 계산 결과를 숫자로 나타낼 수 없음 |

`.5`(= 0.5)와 `3.`(= 3)처럼 소수점 한쪽에만 숫자가 있는 수는 허용한다.

**결과 표시**: 유효숫자 최대 10자리로 반올림하고 끝의 0은 지운다. 절댓값이 10¹⁰ 이상이거나 10⁻⁶ 미만(0 제외)이면 `a×10^n` 꼴로 보인다. −0은 0으로 보인다. 정답 판정용 반올림(예: "소수 둘째 자리까지")은 학습자가 미션 지시에 따라 직접 한다.

### 3. Learning Goals

1. 학습자가 계산을 옮겨 적는 일보다 식의 의미와 단위(m/s↔km/h)를 따지는 데 시간을 쓴다
2. 학습자가 식을 세운 뒤 계산기로 값을 구하고, 그 값을 무전 입력란에 직접 옮겨 적으면서 상황에 맞는 크기인지 스스로 판단한다

### 4. Core Interaction

- **접힌 상태**: 화면 오른쪽 아래에 고정된 원형 버튼(44px 이상). 화면을 스크롤해도 같은 자리에 있다. 오른쪽 위는 언어 버튼, 아래 가운데는 튜토리얼 카드 자리라서 오른쪽 아래로 정함 (사람 결정)
- **펼친 상태**: 식 표시줄, 결과줄, 닫기(×), 자체 키패드. 키는 23개다: `0`~`9`, `.`, `+` `−` `×` `÷`, `^` `√` `(` `)` `π`, `⌫`(한 글자 지우기), `C`(모두 지우기), `=`. **5열 배치**이고 키는 모두 44×44px 이상이다. 휴대폰 기본 키보드는 띄우지 않는다
- **계산**: `=`를 누르면 결과줄에 값이나 오류 이유가 나온다. 식을 고치면 결과줄은 비워진다
- **접기**: 원형 버튼을 다시 누르거나, 닫기(×)를 누르거나, Esc를 누르면 접힌다. **바깥을 눌러도 접히지 않는다.** 무전 입력란도 계산기 바깥(카드 안)에 있어서, 입력란을 누를 때 결과가 사라지면 옮겨 적을 수 없기 때문이다 (Issue 초안 "바깥을 누르면 접힘"에서 바꿈, 사람 확인 2026-11-11)
- **식 유지**: 접었다 다시 펼쳐도 식과 결과는 `C`를 누를 때까지 남는다
- **튜토리얼 카드와 함께 열릴 때**: 카드(아래 고정, 최대 화면 높이의 48%)는 그대로 두고, 계산기를 **카드 위쪽 빈자리**에 펼친다. 360×640에서 카드와 계산기가 겹치지 않고 함께 보여야 한다. 화면이 더 낮아 겹치게 되면 계산기가 카드 위에 온다. 겹침 순서는 튜토리얼 카드(1001)보다 위, 툴팁(1100)보다 아래 (사람 결정)
- **"답 넣기" 버튼은 없다**: 결과를 입력란에 자동으로 넣지 않는다. 학습자가 값을 보고 직접 옮겨 적는다 (사람 결정, 학습 목표 2)

### 5. Progression — 계산기가 보이는 단계

계산기를 켜고 끄는 것은 에피소드가 단계마다 정한다. 엔진은 "이 단계에서 계산기를 보일지"만 받는다.

| 에피소드 | 계산기 버튼이 보이는 곳 | 보이지 않는 곳 |
|---|---|---|
| 02 레이스 엔지니어 | 무전 입력란이 있는 미션 단계 (M2~M8의 계산 단계), 튜토리얼이 끝난 뒤 자유 조작 | 설명·예상(어림)·퀴즈 단계, 튜토리얼 시작 전 첫 화면 |
| 01 자주포 | 이번에는 켜지 않음 (숫자를 입력하는 곳이 없음). 엔진은 지원하므로 나중에 켤 수 있다 | 전부 |

- 계산기가 펼쳐진 채 계산기가 보이지 않는 단계로 넘어가면, 계산기를 접고 버튼도 숨긴다. 식은 남는다
- 계산기를 쓰는지 여부는 판정과 진행 기록에 영향을 주지 않는다

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 무전 입력 단계에서 식을 계산한다 (Priority: P1)

학습자가 M3 "비가 온다" 단계에서 젖은 노면의 그립 한계를 구해야 한다. 오른쪽 아래 계산기 버튼을 눌러 `√(1.0×9.8×80)×3.6`을 입력하고 `=`를 누른다. 결과를 보고 무전 입력란을 눌러 직접 값을 적어 보낸다.

**Why this priority**: 이 미션의 존재 이유다. 이것만 있어도 학습자가 별도 앱 없이 미션을 풀 수 있다.

**Independent Test**: 360×640에서 M3 단계를 열고 키패드만 눌러 식을 입력해 결과를 확인한 뒤, 그 값을 입력란에 적어 통과하는지 본다.

**Acceptance Scenarios**:

1. **Given** 무전 입력란이 있는 단계, **When** 계산기 버튼을 누른다, **Then** 계산기가 카드 위쪽에 펼쳐지고 휴대폰 기본 키보드는 뜨지 않는다
2. **Given** 펼친 계산기, **When** 키패드로 식을 입력하고 `=`를 누른다, **Then** 결과줄에 식 계산 규칙에 맞는 값이 유효숫자 최대 10자리로 나온다
3. **Given** 결과가 나온 계산기, **When** 카드 안 무전 입력란을 누른다, **Then** 계산기는 접히지 않고 결과가 그대로 보인다
4. **Given** 결과를 옮겨 적은 입력란, **When** 보낸다, **Then** 계산기를 쓰지 않고 같은 값을 적었을 때와 똑같이 판정된다
5. **Given** 360×640 화면, 카드와 계산기가 함께 열림, **When** 화면을 본다, **Then** 카드의 문제 문구·입력란과 계산기 키가 서로 가리지 않는다

---

### User Story 2 - 같은 식은 언제나 같은 값이 나온다 (Priority: P1)

학습자가 교과서에서 본 대로 `-2^2`, `2π`, `√9+7`, `1÷2π` 같은 식을 입력하면, 교과서 관례대로 해석한 값이 나온다. 규칙에 맞지 않는 식은 엉뚱한 값 대신 무엇이 잘못됐는지 알려 준다.

**Why this priority**: 계산 규칙이 흔들리면 학습자는 맞게 세운 식으로 틀린 답을 보내게 된다. 판정 신뢰가 무너지는 오류다.

**Independent Test**: 화면 없이 식 해석 함수에 `answers.md`의 사례를 넣어 기대값·오류와 비교하는 단위 테스트.

**Acceptance Scenarios**:

1. **Given** 2절 우선순위 표의 예시 식, **When** 계산한다, **Then** `answers.md`의 기대값과 같다 (상대 오차 1e-12)
2. **Given** 오류로 처리하는 식 (빈 식, 괄호 짝 불일치, `1÷0`, `√-4` 등), **When** `=`를 누른다, **Then** 값 대신 한/영 오류 이유가 나온다
3. **Given** `0.1+0.2`, **When** 계산한다, **Then** `0.3`으로 보인다

---

### User Story 3 - 필요한 단계에서만 계산기가 보인다 (Priority: P2)

학습자가 M2 "드라이버의 두 번째 질문"에서 "계산하기 전에 먼저 예상해 보세요"라는 문구를 읽을 때는 계산기 버튼이 없다. "M2 몇 배 빨라졌나요?" 무전 입력 단계로 넘어가면 버튼이 나타난다.

**Why this priority**: 어림 감각을 보는 단계에서 계산기가 보이면 학습 의도가 깨진다. 다만 P1 없이는 의미가 없으므로 P2.

**Independent Test**: 튜토리얼을 단계별로 넘기며 버튼 표시 여부를 5절 표와 비교한다.

**Acceptance Scenarios**:

1. **Given** 레이스 엔지니어 설명·예상·퀴즈 단계, **When** 화면을 본다, **Then** 계산기 버튼이 없다
2. **Given** 무전 입력란이 있는 단계, **When** 화면을 본다, **Then** 계산기 버튼이 있다
3. **Given** 계산기를 펼친 무전 입력 단계, **When** 다음 단계(설명)로 넘어간다, **Then** 계산기가 접히고 버튼이 사라진다. 다시 무전 입력 단계에 오면 버튼이 나타나고, 펼치면 이전 식이 남아 있다
4. **Given** 튜토리얼을 끝낸 자유 조작, **When** 화면을 본다, **Then** 계산기 버튼이 있다
5. **Given** 자주포 에피소드, **When** 어느 단계든 본다, **Then** 계산기 버튼이 없다

---

### User Story 4 - 접고 펼치기 (Priority: P2)

학습자가 계산을 끝내고 원형 버튼, 닫기(×), Esc 중 하나로 계산기를 접는다. 다시 펼치면 마지막 식이 남아 있다.

**Acceptance Scenarios**:

1. **Given** 펼친 계산기, **When** 원형 버튼·닫기(×)·Esc 중 하나를 누른다, **Then** 접힌다
2. **Given** 식이 있는 채 접힌 계산기, **When** 다시 펼친다, **Then** 식과 결과가 그대로다
3. **Given** 펼친 계산기, **When** `C`를 누른다, **Then** 식과 결과가 모두 지워진다. `⌫`는 마지막 한 글자만 지운다

### Edge Cases

- 식이 길어 한 줄을 넘으면 표시줄 안에서 줄바꿈되고, 계산기 너비는 변하지 않는다
- 튜토리얼 카드의 툴팁(1100)은 계산기 위에 보인다
- 언어를 바꾸면 계산기 라벨·오류 문구도 바뀌고 식은 남는다
- `√` 뒤에 아무것도 없거나 `^`로 끝나는 식은 "연산자로 끝남"과 같은 식 오류다
- 화면 높이가 640px보다 낮으면 계산기가 카드 일부를 덮을 수 있다 (계산기가 위)

## Requirements *(mandatory)*

### Functional Requirements

### Key Entities

- **식 (expression)**: 학습자가 키패드로 입력한 기호의 나열. 숫자, π, 연산자, 괄호, √로 이루어진다
- **결과 (result)**: 식을 계산한 값 또는 오류 이유. 값은 표시 규칙에 따라 문자열로 보인다
- **단계별 계산기 설정**: 에피소드가 각 단계에 정하는 "계산기 보임 / 숨김"

## Success Criteria *(mandatory)*

- **SC-001**: 무전 입력 단계에서 학습자가 화면을 떠나지 않고 M3 식을 계산해 보내기까지 걸리는 조작이 "버튼 1번 + 키 입력 + `=` + 옮겨 적기"이다 (지금은 다른 앱으로 전환)
- **SC-002**: `answers.md`의 모든 검증 사례에서 기대값과 다른 값이 0건이다
- **SC-003**: 360×640에서 카드와 계산기가 겹치는 넓이가 0이고, 44px 미만 조작 요소가 0개다
- **SC-004**: 계산기가 보이면 안 되는 단계(설명·예상·퀴즈, 자주포 전체)에서 계산기 버튼이 보이는 경우가 0건이다
- **SC-005**: 계산기 도입 전후 같은 입력값에 대한 판정 결과의 차이가 0건이다 (기존 브라우저 테스트 무수정 통과)

## Assumptions

- 정식 경로: 계산 코드(식 해석기) 추가와 단계별 표시(학습 흐름 변경)가 들어가므로 가벼운 경로 조건에 맞지 않음 (Issue #31 난이도 3)
- 사람 결정 2026-11-11: 계산 규칙 교과서 관례 (DM-01M755VRM6SGKKKQV4BNQE00NA), 붙여 쓴 곱을 먼저 (DM-01M7566RN230J5W8CBCFQP595M), 오른쪽 아래 고정 (DM-01M755VXM02R2YBVW6KRXD7GR2), 카드 위쪽에 펼침 (DM-01M755W3D894W7XJTA5C39YP63), 답 넣기 없음 (DM-01M755W9D4M9C8MPRZVC6C6K01), 무전 입력 단계와 자유 조작에서만 보임 (DM-01M7562YAK5Q1V8FZZ4YGHTBM8)
- 메인 세션 제안을 사람이 수락함 (2026-11-11): 바깥을 눌러도 접히지 않음, 유효숫자 10자리, 접어도 식 유지, 컴퓨터 키보드 입력은 범위 밖
- 키패드 높이(5행)와 카드 최대 높이(48vh ≈ 307px)를 합치면 640px 안에 들어간다는 것은 계산값(약 310 + 307px)이라, 구현에서 렌더 측정으로 확인한다 (NFR-002). 들어가지 않으면 멈추고 사람에게 묻는다
- 튜토리얼이 끝난 뒤 자유 조작에는 무전 입력란이 없지만, 학습자가 직접 값을 실험할 때 쓰도록 계산기를 보인다 (사람 결정)
