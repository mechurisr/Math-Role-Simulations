### 4. Core Interaction

지금 이 단계는 원의 방정식을 앞 단계에서만 보여 주고, 계산기는 답 입력란이 있는 단계에서만 켜져 여기서는 쓸 수 없다. 학습자는 식을 기억해 다섯 곳을 암산하거나 지도 모양으로 찍게 된다. 바뀐 뒤에는 화면 안에서 식을 보며 대입하고 계산기로 값을 구해 적어 둘 수 있다.

| 화면 요소 | 지금 | 바뀐 뒤 |
|---|---|---|
| 원의 방정식 | 앞 단계 "원의 방정식"에만 | 이 단계 문제 문단 위에도 같은 식 |
| 계산기 | 이 단계에서 숨김 | 사용 가능. 결과는 계산기 자신의 결과 줄에 표시 (추가 표시 없음) |
| 후보 줄 | 좌표 · [원 위] [아님] | 좌표 · [메모 칸] [원 위] [아님] |
| 메모 칸 | 없음 | 숫자를 적어 두는 칸. 채점·판정에 쓰지 않음 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 식을 보며 직접 대입한다 (Priority: P1)

M3 판정 단계에 온 학습자가 화면의 원의 방정식을 보고, 계산기로 각 후보의 좌변 값을 구해 그 후보 줄의 칸에 적은 뒤, 그 값과 우변을 비교해 "원 위 / 아님"을 고른다.

**Acceptance Scenarios**:

1. **Given** M3 "진앙 후보 가려내기" 단계, **When** 단계에 들어간다, **Then** 문제 문단 위에 원의 방정식이 보이고 계산기 버튼이 보인다
2. **Given** 같은 단계, **When** 후보 줄을 본다, **Then** 다섯 줄 모두 "원 위" 버튼 왼쪽에 메모 칸이 있다
3. **Given** 메모 칸에 값을 적었다, **When** "원 위/아님"을 누르거나 "판정 확인"을 누르거나 언어를 바꾼다, **Then** 적은 값이 그대로 남아 있다
4. **Given** 메모 칸에 아무 값(틀린 값 포함)을 적었다, **When** 판정을 확인한다, **Then** 판정 결과와 통과 여부는 버튼 선택만으로 정해진다 (지금과 같음)
5. **Given** 앞뒤 단계(답 입력란이 없는 단계), **When** 들어간다, **Then** 계산기는 지금처럼 숨겨진다

### Edge Cases

- 360px 폭에서 한 후보 줄(좌표·칸·두 버튼)이 한 줄에 들어가고, 화면 가로 스크롤이 생기지 않으며, 버튼과 칸의 터치 영역이 44px 이상이다
- 휴대폰에서 칸을 누르면 숫자 키보드가 뜬다
- 단계를 떠났다가 다시 들어오면 지금처럼 선택이 초기화되고, 메모도 함께 비워진다
- 칸을 탭해도 지도나 튜토리얼 진행이 바뀌지 않는다

## Requirements *(mandatory)*

### Functional Requirements

| ID | Title | User Story | Priority | Status |
|----|-------|------------|----------|--------|
| FR-001 | 식 표시 | 학습자로서, M3 판정 단계의 문제 문단 위에서 앞 단계와 같은 원의 방정식을 보고 싶다 | High | Open |
| FR-002 | 메모 칸 | 학습자로서, 후보마다 "원 위" 버튼 왼쪽의 칸에 계산한 값을 적어 두고 싶다. 칸의 값은 채점·판정·진행 조건에 쓰이지 않고, 그 단계에 머무는 동안 다시 그려져도 유지된다 | High | Open |
| FR-003 | 계산기 사용 | 학습자로서, M3 판정 단계에서도 계산기를 열어 쓰고 싶다. 결과는 계산기 화면에 보인다. 다른 단계의 계산기 표시 규칙은 그대로다 | High | Open |

## Success Criteria *(mandatory)*

- **SC-001**: M3 판정 단계에서 학습자가 화면을 떠나지 않고 식 확인·계산·기록·판정을 모두 할 수 있다 (식 1개, 메모 칸 5개, 계산기 사용 가능)
- **SC-002**: 판정 결과와 통과 조건의 변화 0 (기존 M3 e2e 무수정 통과)
- **SC-003**: 360px 폭에서 가로 스크롤 0, 44px 미만 터치 영역 0
