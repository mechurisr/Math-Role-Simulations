# Research: 레이스 엔지니어

## R1. 그래프 공유 방식 (사람 결정, 2026-10-31)

- **Decision**: 엔진에 범용 축척·축·곡선 도구(`engine/src/ui/plot.ts`)를 새로 만든다. 01의 `view/chart.ts`는 그대로 둔다
- **Rationale**: 01 차트는 게임 상태 `S`에 묶인 2단·넓이 칠하기 전용 코드라 겹치는 부분이 축과 곡선뿐이다. 재작성하면 이전 비교 위험이 이번 미션에 들어온다(C-003)
- **Alternatives**: 01 차트까지 다시 작성 — 중복은 없어지지만 위험과 비용이 늘어 기각

## R2. 수식 표시 (사람 결정)

- **Decision**: 브라우저 기본 MathML. 엔진에 작은 헬퍼(`engine/src/ui/formula.ts`)를 둔다
- **Rationale**: 런타임 의존성 없음. MDN 기준 Baseline widely available
- **Alternatives**: KaTeX(폰트·CSS 부담), Temml(LaTeX 문법이 필요할 때의 대안). 유니코드 텍스트는 분수·근호를 읽기 어려움
- **확인 항목**: 360px 줄바꿈, 다크 테마 색, Firefox·WebKit 표시

## R3. 그래프 축 (FR-006, 스펙 검토 반영)

- **Decision**: 가로축은 교점이 보이도록 340 km/h에서 1000 km/h까지 넓어진다. 세로축은 표시 범위 안의 값에 맞춘다. 교점이 1000 km/h를 넘으면 "교점이 축 밖", 경계 이상이면 "교점 없음(한계 없음)"
- **Rationale**: 고정 축이면 r = 122.58 m에서 교점이 화면 밖으로 나가 경계 156.25 m의 사라짐을 볼 수 없다
- **Alternatives**: 점근선 표시 — 학습자에게 설명할 개념이 늘어 기각

## R4. 미끄러짐 애니메이션

- **Decision**: 코너 진입 구간에서 표시되는 필요한 힘 막대를 0에서 실제 값까지 올린다. 판정은 계산으로 먼저 정하고 애니메이션은 그 결과를 보여 주기만 한다. 막대가 넘치는 순간의 접선 방향으로 미끄러진다
- **Rationale**: 일정 속도의 원운동에서 필요한 힘은 진입 순간부터 일정해, 그대로 그리면 "차오르는" 모습이 없다. 진입 구간은 곡률이 커지는 구간으로 보면 표현이 자연스럽다
- **단순화 고지**: 막대 상승은 표현이며 판정에 쓰이지 않는다

## R5. 경계 판정

- **Decision**: `m − μkr ≤ 0`을 먼저 검사한다. 판정 여유를 두지 않는다
- **Rationale**: 스펙 검토 토론 결과. 0.01 m 간격 26001점에서 유리수 판정과 불일치 0건, 여유는 오분류를 만든다
- **테스트**: 156.24 / 156.25 / 156.26

## R6. 속성 테스트: fast-check (사람 결정)

- **Decision**: fast-check 4.10.2를 개발 의존성으로 추가하고 시드를 고정한다
- **공급망 점검 (2026-10-31)**: 공식 npm 레지스트리, 저장소 github.com/dubzzz/fast-check, MIT. preinstall·install·postinstall 없음. 2026-09-19 배포로 약 6주 경과. 의존성 `pure-rand` 하나. 번들에 들어가지 않음. Node는 `.node-version` 26. 잠금 파일에 고정하고 `pnpm install --frozen-lockfile`을 유지
- **Adversarial evidence**: `deferred_with_rationale` — 런타임에 포함되지 않고 설치 스크립트가 없는 개발 의존성 하나라 별도 적대적 검토는 생략한다. 설치 시 레지스트리 URL과 잠금 파일 변경을 확인한다
- **Alternatives**: 표 기반 테스트만 — 단조성·경계 성질을 넓게 확인하기 어려움
