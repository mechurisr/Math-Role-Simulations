## 1. 수학 독립 검증

공통 상수 (스펙의 "Staged Missions" 표에서 직접 유도):
Δt = d/Vs − d/Vp = d(1/3.5 − 1/6) = d·(5/42) s → **d = 8.4·Δt km**, 즉 k = 8.4 km/s.
(1/3.5 = 2/7, 2/7 − 1/6 = 5/42. 게임 값 Vp=6.0, Vs=3.5에서 나오는 유도값이며 별도 출처가 필요 없는 값)

### M1 두 파의 경주
- 독립 풀이: 거리 d에서 Δt = d(1/3.5 − 1/6) = 5d/42. d=210 km → Δt = 210×5/42 = 25 s. 선형이므로 거리가 2배·3배면 시간 차도 2배·3배. (d=0이면 Δt=0)
- 스펙 답과 비교: **일치.** answers.md도 25.0 s, 통과 24.5~25.5, 같은 식(210/3.5 − 210/6 = 60 − 35). answers.md의 참고값(84 km에서 14/24 s, Δt 10 s)도 내 k=8.4와 정합.
- 지적: 없음

### M2 시간 차로 거리 구하기
- 독립 풀이: 판독값 Δt에 대해 d = 8.4·Δt. 스펙이 M2의 지진 기록 판독값을 주지 않았으므로, 연습 지도의 관측소 A(12.5 s)를 M2의 기록으로 **가정**하면 d = 12.5×8.4 = **105 km**. (P 도착 t₀, S 도착 t₀+12.5인 기록)
- 확인한 것: 판독 허용오차 ±0.3 s는 거리로 ±2.52 km다. 스펙은 판독 통과 시 "정확한 판독값이 확정되어 표시됨"이라 서술해 이 위험을 일부 막고 있다(순서를 지킨 학습자는 105 km를 얻는다).
- 스펙 답과 비교: **불일치 — 1차 가정이 틀렸다.** answers.md는 M2 기록을 P 21.0 s / S 36.0 s로 정해 S-P = 15.0 s, d = 8.4×15 = **126 km**(통과 124~128)로 두었다. 검산 126/6 = 21, 126/3.5 = 36 — 정확히 정수로 떨어지는 별도 설계다. 1차는 spec.md에 기록값이 없어 연습 지도 A를 가정했고, 공식·계수(k=8.4)는 answers.md와 같다.
- 지적:
  - [사소함] **m14 (R6, 2차에서 하향)** answers.md에 M2 기록 파라미터(21.0/36.0 s)가 명시되어 구현자가 임의로 만들 일은 없다. 다만 **spec.md 본문에는 여전히 없다**. spec.md만 읽는 계획자·구현자는 M2 화면을 만들 수 없고, C-004("모든 물리값 근거를 주석에")·FR-009(조건 표시) 관점에서 spec.md의 M2 카드나 공통 입력 표에 "M2 기록: P 21.0 s, S 36.0 s"를 넣는 편이 안전하다. (치명적 아님 — 정답 파일에 값이 있음)
  - [권장] **R1** 판독 허용오차(±0.3 s = ±2.52 km)와 거리 허용오차(±2 km)의 폭이 맞지 않는다. 15.3 s로 판독해 통과한 학습자가 확정 표시를 놓치고 자기 값으로 15.3×8.4 = 128.52 km를 보내면 정답 126에서 2.52 km 벗어나 **방법은 맞는데 떨어진다**. answers.md도 이 모순을 인지하지 못한 채 "판독 14.7~15.3, 거리 124~128"을 나란히 적었다. 판독을 ±0.2 s로 좁히거나(±1.68 km) 거리를 ±3 km로 넓히는 편이 안전하다. (M7에 같은 문제 — §M7 참고)
  - [사소함] **m1** 판독 통과 뒤 표시값이 학습자가 찍은 값에서 "확정값"으로 바뀌는 것을 안내 문구로 명시해야 한다 (예: "확정된 판독값 15.0 s로 계산하세요").
  - [권장] **R9 (신규)** M2 기록의 시간축 설계. P 첫 도착이 21.0 s, S가 36.0 s면 지진 발생(t=0)에서 21초를 기다려야 첫 흔들림이 온다. 게임은 "방금 지진이 났다"(Role Setting)라 하고 기록을 "관측소에 기록된 땅의 흔들림 그래프"로 정의하므로, 화면 시간축이 **지진 발생 시각 기준 0~40 s**인지 **기록 시작 기준(잘라 낸 구간) 0~15 s**인지가 결정되지 않았다. answers.md는 "화면 시계 표기는 구현 선택"이라고 미뤘지만, 이 선택이 M2 판독 난이도와 화면 폭을 바꾼다(360px에서 40 s 축에 0.3 s 허용오차 = 2.7 px). 시간축 범위·원점·눈금 간격을 answers.md에 확정해 적을 것.

### M3 관측소 하나: 원
- 독립 풀이: A(16,77), Δt=12.5 s → r = 105 km. 원: (x−16)² + (y−77)² = 11025.
  - (121,77): 105²+0 = 11025 → 원 위 (가능)
  - (79,161): 63²+84² = 3969+7056 = 11025 → 원 위 (가능) *(3-4-5의 21배)*
  - (16,182): 0+105² = 11025 → 원 위 (가능)
  - (100,100): 84²+23² = 7056+529 = 7585 < 11025 → 원 안 (불가능)
  - (37,182): 21²+105² = 441+11025 = 11466 > 11025, 거리 √11466 ≈ 107.08 km → 원 밖 2.08 km (불가능)
  - 판정 5개: 가능/가능/가능/불가능/불가능. 반지름 105 km.
- 스펙 답과 비교: **일치.** answers.md도 r_A = 105 km(통과 103~107), 판정 가능/가능/가능/불가능/불가능, (37,182)를 "거리 107.08, 원 밖 약 2.08 km"로 적어 내 계산(107.079)과 같다.
- 지적:
  - [사소함] **m2** 반지름 허용오차가 ±2 km인데, 함정 후보 (37,182)의 어긋남이 2.08 km다. 학습자가 반지름을 107 km로 정해도 통과하고, 그 원에서는 (37,182)가 0.08 km 차이로 "원 위"처럼 보인다. 판정은 원의 방정식 값으로만 한다고 Edge Cases에 적혀 있어 논리적으로는 일관되지만, 시각적 함정의 크기(2.08 km)가 허용오차(2 km)보다 조금만 크다는 점이 불편하다. 함정을 3 km 밖으로 옮기거나 반지름 허용오차를 ±1 km로 줄이면 깔끔하다.
  - [권장] **R7 (신규, 허용오차 연쇄)** "반지름 ±2 km 통과"와 "5개 판정 모두 맞음"을 동시에 요구하는데 **세 '원 위' 후보가 정확히 105.000 km**에 있다. 판정이 학습자가 입력한 r로 계산된다면 r = 106이 (37,182)를 1.079 km 차이로 "원 위"라 하고, r = 107은 105 km 후보들을 "원 밖"이라 한다. 정밀 계산으로 |d−r|의 부등호가 뒤집히는 경계는 **r = 106.04 km**다. Edge Case가 "거리·반지름은 소수를 받는다"고 했으므로 106.5나 107을 넣는 학습자는 **반지름 단계는 통과하고 판정에서 떨어진다**. SC-001("허용 오차 안 답은 100% 통과")의 직접 위반이다. 해결: (a) 반지름 허용오차를 ±1 km로 줄이고, (b) 판정을 정답 반지름 105 기준으로 고정할지 학습자 입력 기준으로 할지 스펙에 못박고(현재 Edge Case는 "학습자가 넣은 값을 그대로"라고만 씀), (c) 후보 (37,182)를 3 km 밖으로 옮긴다. answers.md의 "정수 연산으로 정확히 판정"은 **정답 반지름 105에서만** 성립한다는 점도 함께 적어야 한다.

### M4 관측소 둘: 두 원이 만나는 직선
- 독립 풀이: B(100,77), Δt=7.5 s → r_B = 63 km, r_B² = 3969. 두 중심 거리 d = 84.
  - |105−63| = 42 ≤ 84 ≤ 168 → 교점 2개 (탐색 구간: r_B < 21 → 없음, =21 → 접함, 21<r_B<189 → 2개, =189 → 접함, >189 → B가 A를 포함해 없음)
  - 펼치기: A: x²+y²−32x−154y−4840 = 0 (256+5929−11025 = −4840), B: x²+y²−200x−154y+11960 = 0 (10000+5929−3969 = 11960)
  - 빼기: 168x − 16800 = 0 → **x = 100**, 즉 a=1, b=0, c=100 (또는 −1, 0, −100 등 0이 아닌 상수배)
- 스펙 답과 비교: **일치.** answers.md도 168x − 16800 = 0 → x = 100, (a,b,c) = (1,0,100)과 상수배, 판정은 정규화 후 성분 1e-6 이내. 근축이 수직선이 되는 것도 "첫 경험에서 계산이 깔끔하도록 고른 배치"로 명시해 1차 관찰(R2)과 같은 사실을 인정한다.
- 지적:
  - [권장] **R2** A와 B가 같은 y=77 위에 있어 근축이 **수직선 x=100**으로 퇴화한다. 빼는 과정에서 y항까지 함께 사라져, 학습자는 "이차항이 사라진다"는 것만이 아니라 "y가 아예 없는 직선"을 보게 된다. 학습 목표 3(일반형 ax+by=c)을 확인하려면 B를 y=77이 아닌 곳에 두어 a, b가 모두 0이 아닌 근축을 한 번은 다루게 하는 편이 좋다. 지금 수치는 M3·M5·M6 정답이 모두 정수로 떨어지는 장점이 있으므로, "M4에서 일반형을 한 번 더" 넣거나 B 좌표만 조정하는 선택지가 있다. answers.md는 "일반 직선은 M8 계산(설명용)과 M7 지도에서 나온다"고 하나 **M8 ②는 학습자가 직선을 입력하지 않고**, M7도 계수 입력이 아니라 원 교점이다 → 일반형을 직접 다루는 지점이 실제로 없다.
  - [사소함] **m15 (m3, 2차 해소)** answers.md가 "입력 계수를 절댓값 최대 성분으로 나눈 정규형이 정답 정규형과 성분마다 1e-6 이내(부호를 맞춘 뒤)"로 판정 규칙을 확정했고, 단위 테스트 항목(상수배·부호 반전 통과, a=b=0 거부)도 있어 1차 우려는 해소됐다. §4의 구현 지적은 answers.md 규칙을 그대로 옮기면 된다.
  - [권장] **R8 (신규, M4의 허용오차 연쇄)** r_B 허용오차 ±2 km인데 직선은 **정확한 같은 직선**을 요구한다. 근축 식 x = (r_A² − r_B²)/168 + 84 이므로 r_B = 63±2면 직선이 **x = 100 ± 1.49 km**로 움직이고, 그 직선은 두 교점도 ±1.49 km 옮겨 간다(r_B=61 → x=101.48, r_B=65 → x=98.48). 그러면 학습자는 "내 r_B로 식을 세웠는데 내 직선이 틀렸다"는 모순을 겪는다. M4는 "직선이 지도에서 두 교점을 지나는지 확인"을 요구하므로 **자기 일관성**은 지켜지지만, 정답 판정은 M4의 반지름(63) 기준 직선만 통과시킨다. 해결: r_B 허용오차를 ±1 km로 줄이거나(직선 오차 ±0.74 km), M4 직선 판정을 "학습자가 정한 r_B로 만든 근축"과 비교하도록 스펙에 명시하고 answers.md에 그 식을 적는다. 지금대로면 정답 반지름 근처에서 반올림한 학습자가 방법은 맞는데 떨어진다.

- 지적:

### M6 관측소 셋: 진앙 확정
- 독립 풀이: C(184,140), Δt=10.0 s → r_C = 84 km.
  - (100,140): 84²+0² = 7056 = 84² → C의 원 위 ✓
  - (100,14): 84²+126² = 7056+15876 = 22932, 거리 ≈ 151.4 km ✗
  - → 진앙 **C(100,140)**, 세 원 모두 위에 있다 (A 105, B 63, C 84 모두 정확히 일치).
- 스펙 답과 비교: **일치.** answers.md도 진앙 (100,140), r_C = 84, (100,14)까지 √22932 ≈ 151.43으로 탈락, 세 원 모두 상대 오차 1e-9로 통과. (100,14)는 B·C 교점이 아니라 두 원만의 교점 하나이므로 "B·C 교점 후보"라는 1차 서술은 부정확하지만 결론은 같다.

## 3. 교육 설계

- 순서: M1(비례 관찰) → M2(역산 공식) → M3(원 = 한 점에서 거리가 같은 점) → M4(식을 빼서 직선) → M5(직선으로 교점) → M6(세 원 → 한 점) → M7(실제 사례 적용) → M8(오차·잔차). 학습 목표 1→2→3이 미션 순서와 정확히 대응하고, 각 미션의 입력이 다음 미션의 입력이 된다(거리 → 반지름 → 교점 → 진앙). 건너뛰는 개념은 없다: 제곱 전개·이차방정식·피타고라스는 선수 지식으로 명시되어 있고 M3~M5에서 쓰인다(단 이차방정식의 사용 강도는 m4 참고).
- [권장] **R4** M8에서 **"왜 제곱합인가"**(부호가 있는 잔차를 그냥 더하면 상쇄된다)를 설명하는 단계가 없다. §③은 "최소점이 진짜 진앙과 같다는 보장은 없다"만 다룬다. 잔차 막대에서 +와 −가 함께 보이는 순간에 한 줄 설명(절댓값은 다루기 어려워 제곱)을 넣으면 새 기준이 임의로 보이지 않는다. answers.md도 절댓값·제곱 선택 이유를 따로 적지 않아 이 공백이 그대로 구현으로 넘어간다.
- [권장] **R13 (신규, 평가 순서)** 1차는 "건너뛰는 개념은 없다"고 봤고 그 판단은 유지한다. 다만 **M7이 학습 목표 1(판독→거리)을 다시 평가하지 않는다**. M7 통과 조건은 "세 S-P ±0.3 s, 세 거리 ±2 km, 좌표 ±5 km"인데 판정이 한꺼번에 이뤄지고, R10의 지름길(P 도착 × 6)로 판독을 우회할 수 있다. 학습 목표 3(원의 교점)이 이 에피소드의 핵심인 만큼 M7에서도 **판독을 먼저 통과해야 거리 입력이 열리고, 세 거리가 확정된 뒤에 원이 그려지는** 순서를 스펙에 명시할 것. 그러면 R10과 m8(판독 3개 부담)이 동시에 완화된다.
- [사소함] **m8** M7에서 지진 기록 세 개를 각각 ±0.3 s로 읽는 것이 이 에피소드의 최종 평가인데, M2에서 한 번만 연습하고 바로 세 개로 늘어난다. M6 뒤에 판독 연습을 한 번 더 두거나, 세 기록을 탭으로 하나씩 처리한다는 점을 미션 카드에 명시하면 부담이 줄어든다. R13의 순서 강제와 함께 처리하면 자연스럽다.
- 좋은 점(지적 아님): M1의 "2배·3배 예상 먼저", M4의 "교점 개수 탐색 먼저"가 모두 예측→확인 구조다. M8 ③이 "측정에 가장 잘 맞는 점 ≠ 진짜 진앙"을 명시해 C-007과 일치한다. M7이 "게임용 가상 관측소"임을 표에 적어 실제 관측소로 오해할 여지를 없앴다. 선수 지식 목록이 실제 미션에서 쓰는 도구와 대체로 맞는다.

## 4. 구현 가능성

- [권장] **R3(구현 지적)** M8 ②의 ±1 km는 200 km 지도·360px에서 약 1.8 px다. 지진 기록 마커의 ±0.3 s도 손가락으로는 경계선이다. 확대/이동, 1 km·0.1 s 단위 스냅, 미세 조정 버튼 중 하나를 스펙에 명시해야 PRJ-004(터치로 끝까지)를 만족한다. M8 ②는 이 보완이 없으면 완주 자체가 어렵다. 참고로 M8 ②의 F 지형은 최소점 근처에서 매우 평평하다(1 km 이동에 F가 5.66 → 7.01~7.29, 약 25% 증가). 즉 **판정은 구별되지만 손가락으로는 안내가 없으면 어디가 더 낮은지 감으로 알기 어렵다**. 잔차 제곱합 수치를 실시간으로 크게 표시하는 것(FR-018)이 사실상 필수다.
- [권장] **R12 (신규)** **M3·M4의 판정 기준을 스펙에 명시해야 한다.** Edge Case는 "좌표 판정은 학습자가 넣은 값 그대로 정답과의 평면 거리로 한다"고만 쓰고, **반지름·직선 같은 중간값 판정**은 "학습자가 넣은 값 기준"인지 "정답 값 기준"인지 없다. 이 구분이 R7(M3 판정)·R8(M4 직선)의 원인이다. 구현자가 답을 정할 수 없으므로(PRJ-005의 모호함) 스펙에 규칙을 적어야 한다: (a) M3 후보 판정은 **학습자가 정한 반지름 r로** 계산한다면 후보 오프셋과 허용오차가 맞물려야 하고, (b) M4 직선은 **학습자가 정한 r_B로 만든 근축**과 비교할지 고정 정답 직선과 비교할지 정해야 한다. 권장: 판정은 모두 "정답 값" 기준으로 고정하고, 중간값 허용오차만 통과용으로 두되 **통과 즉시 정답값으로 스냅해 확정 표시**(m1 방식)한다. 이러면 R1·R7·R8이 한 번에 해소된다.
- [권장] **R5** **M7 해안선과 km 눈금의 투영 일치.** 정적 해안선 그림을 쓰므로(C-009), 그림의 투영이 km 격자와 같은 등방형(경도에 cos φ_ref 적용)이어야 한다. 어긋나면 USGS 진앙 점과 해안선이 화면에서 서로 다른 곳을 가리켜 "실제 사례"의 신뢰가 깨진다. 그림 제작 시 격자 기준점을 함께 고정할 것. **R11의 φ_ref = 36.0°와 같은 값을 써야 한다**(해안선 그림만 35.0°로 만들면 USGS 점이 해안선에서 1.4 km 어긋난다 — 계산: 1.2162° × 89.96 vs 91.09 km/°).
- [사소함] **m9** 지도 범위가 정의되지 않았다. A의 원 r=105 km는 중심 x=16에서 서쪽으로 x=−89까지, M4 슬라이더 최대 250 km는 더 멀리 나간다. 0~200 격자만 그리면 원이 잘린다. 지도 여백(예: −100~300) 또는 잘림 표시 규칙을 계획에 넣어야 한다. M7에서도 원 1(r ≈ 92.4, 중심 (30,40))이 서쪽·남쪽으로 지도 밖으로 나간다(x ≈ −62, y ≈ −52).
- [사소함] **m10** M8 ①의 반지름 기준이 화면에서 모호해질 수 있다. 같은 화면에 C의 반지름 84(옛)와 88.2(새)가 함께 보이면 학습자가 84로 계산해 제곱합 0을 보낸다. "C의 원은 10.5 s로 다시 그린 88.2 km"를 잔차 패널에 고정 표시할 것. answers.md의 ① 정답(17.64)도 이 전제에 의존한다.
- [사소함] **m3(구현 지적)** M4 직선 판정은 정규화한 (a,b,c)의 상대 오차 허용으로 구현한다. 0이 아닌 상수배만 허용하고 a=b=0은 안내한다는 Edge Case는 그대로 유효하다. answers.md의 "절댓값 최대 성분으로 나눈 정규형, 성분마다 1e-6(부호 맞춘 뒤)"를 그대로 옮기면 된다.
- [사소함] **m11** M8의 최소점은 닫힌 공식이 없고, 선형화하면 근심이 되어 C-006과 어긋난다. 구현은 격자 탐색 + 국소 정련으로 정답을 만들고 NFR-003(1e-9) 기준값을 고정해야 한다. **answers.md가 이미 "0.05 km 격자에서 (97.15, 141.00) / 가우스–뉴턴 수렴값 / ∇F = 0 확인"을 적어 이 지적은 해소**됐다. 다만 NFR-003의 1e-9는 **닫힌 해가 없는 문제에 적용하기 어렵다.** 반복 최소화는 초기값·정지 조건에 따라 마지막 자리가 달라지므로, NFR-003을 **M8 ②에 한해 "1e-6 km + F 1e-6 km²"처럼 완화**하거나 "같은 초기값·같은 반복 횟수로 결정적"이라는 조건을 붙여야 한다. 현재 문구 그대로면 테스트가 불안정해진다.
- 문제 없음으로 본 부분: 교점 0·1·2 판정을 |r₁−r₂| ≤ d ≤ r₁+r₂로 먼저 거르는 순서(Edge Case)는 음수 제곱근을 막는 올바른 구현 지침이다. 결정성(난수 없음), 단위 표시, 언어 전환 시 입력 유지, 좌표 판정에 학습자 입력값을 그대로 쓰는 규칙도 구현 가능한 범위다. M8 ②의 국소 최소가 둘뿐이고 시작점을 (100,140) 근처에 두면 먼 최소(F ≈ 791)로 갈 일이 없다는 answers.md의 판단도 1 km 격자 전수 확인으로 맞다.
